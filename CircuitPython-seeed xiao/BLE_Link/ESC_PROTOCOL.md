# ESC 控制原型 v1（仅模拟）

本次没有电机输出代码，不导入 PWM/GPIO 驱动。`code.py` 只构造 `SimulatedESC`。
`throttle` 是模拟执行层设定值，不是转速或电流反馈。真实 iPhone/XIAO BLE、iOS 编译与电调均未在本环境验证。
将 `code.py` 和 `esc_protocol.py` 一起复制到 CIRCUITPY；保留原有 adafruit_ble 依赖。

## 消息与状态

沿用原 GATT UUID、UTF-8 JSON、换行分帧、20 字节发送分块；单帧上限 4096 字节。
文本 `{ "id":1, "text":"hello" }` 及其响应格式保持兼容。
先发 `{ "v":1, "id":2, "cmd":"STATUS" }`，从响应取得本连接 `session`。
新连接每次生成随机 session。会话令牌用于隔离旧命令，**不是身份认证**。

| 命令 | 额外字段 | 条件与效果 |
| --- | --- | --- |
| STATUS | 无 | 查询当前状态，不续期 |
| ARM | session, throttle:0 | 仅 DISARMED 可进入 ARMED，输出保持 0 |
| SET_THROTTLE | session, throttle:0…1000 | 仅 ARMED；整数，拒绝布尔、浮点、字符串、越界值 |
| DISARM | 无 | 总是停机；不清除 ESTOP 锁存 |
| ESTOP | 无 | 总是停机并锁存 ESTOP |
| RESET_ESTOP | session | 仅 ESTOP；清除锁存进入 DISARMED，必须另发 ARM |

示例：

```json
{"v":1,"id":3,"cmd":"ARM","session":"从 STATUS 获取","throttle":0}
{"v":1,"id":4,"cmd":"SET_THROTTLE","session":"从 STATUS 获取","throttle":100}
{"v":1,"id":5,"cmd":"ESTOP"}
```

响应结构：

```json
{"id":4,"ok":true,"control":{"state":"ARMED","throttle":100,"mode":"simulation","reason":"throttle","session":"本连接令牌","timeout_ms":1500}}
```

错误响应 `ok:false` 加 `error`（如 INVALID_THROTTLE、NOT_ARMED、INVALID_SESSION、STALE_OR_CONFLICTING_ID）。
控制响应包含最新状态；格式损坏、文本验证错误可能只有 id/ok/error。
ID 必须是 0…2147483647 的整数；非停机控制使用严格递增 ID。
仅最近一次成功的改变状态命令可按原 ID 和完全相同内容重试，返回 `duplicate:true`，不重做、不续期；同 ID 改内容或更旧 ID 拒绝。
STATUS、文本与失败请求不推进控制 ID，也不续期。停机命令在 ID 合法时无条件执行，忽略版本/会话/旧 ID，优先停机；重复停机仍停机。
不要自动重试 ARM/油门；发送结果未知时先停机、查询。

从 ARM 或新的 SET_THROTTLE 起 1.5 秒无有效更新，进入 DISARMED、输出归零，必须重新 ARM。
断线或 BLE 服务异常由 finally 停机；重连输出为零、会话更换；ESTOP 锁存跨重连保持。
断电/软重启从 DISARMED 开始，不保留 ESTOP，但绝不自动解锁或恢复油门。

## iOS 行为与限制

原文本演示保留。新增模拟模式/板端状态、油门滑块、零油门 ARM、手动发送油门、DISARM、ESTOP、清除急停。
每 0.5 秒空闲时查询状态；没有自动油门续期。滑块本身不发送。
离开前台主动断开；系统挂起或手机失联时由板端有效期负责停机。
传输空闲时 ESTOP 发出协议命令。若已有半帧正在发送，不能插入另一条 JSON，急停按钮改为请求断开；此路径是失联停机，**没有 ESTOP 锁存确认**，必须重连查零并再次发送 ESTOP。
iOS 显示最后一次回传状态，不能作为物理停机证据。

当前循环检查有效期，收包、空闲和回复分块之间均检查；BLE 底层调用可能阻塞（TX 配置 1 秒超时），因此 1.5 秒是协议逻辑阈值，**不是实测硬实时停机上界**。
模拟器不受阻塞产生机械风险；接真实驱动前必须实现独立于 Python/BLE 循环的硬件失效保护，不能直接把模拟器换成 PWM 就投入使用。
BLE 未加认证/授权，附近设备可能连接控制；实际硬件阶段需另行设计绑定与访问控制。

## 自动验证

仓库根目录：`python -m unittest discover -s tests -v`。
GitHub Actions 自动运行同一命令。协议测试使用注入时钟，无 sleep；另从实际 code.py 提取服务循环进行假 BLE 流测试，覆盖半帧时的超时、服务异常 finally 清理、重连会话/急停保持。
这些测试不证明 CoreBluetooth 或真实无线链路可用。

## 真实 ESC 接入条件（型号确定后再实现）

1. 取得 ESC 数据手册，确认有刷/无刷、单向/双向、PWM/OneShot/DShot/串口等信号类型、频率/电平/脉宽、停止与解锁序列、信号丢失行为。不得假设“1000 µs 就安全”。
2. 确认电池电压、电流、保险、连接器与导线额定值；ESC 动力供电独立设计，不能由 XIAO 的 USB/3.3 V 引脚给电机供电。
3. 非隔离信号通常需要共地，但须按该 ESC 原理图确认；信号电平转换、隔离及 BEC 供电必须核对。不得把未知 BEC 电压接到 XIAO 3.3 V，避免 USB/BEC 反灌。
4. 按板卡官方引脚图选择输出，评估启动/复位/异常时引脚状态。保留物理断电急停、限流和硬件失联停机。先画接线图审查，当前不指定 GPIO 或接线颜色。
5. 独立驱动接口约定：`mode`、`throttle`、`set_throttle(0…1000)`、幂等 `stop()`；驱动内部处理信号映射和 ESC 特定解锁，不向 BLE 协议暴露脉宽。驱动故障须关闭输出并锁存故障，需单独完成实现与测试。

## 分阶段测试与验收门槛

- 阶段 A（当前）：11 项自动测试通过；不连接 ESC/电机。iPhone 连真实 XIAO 后，验证文本回显、状态查询、手动 ARM/油门、1.5 秒逻辑超时、重复 ID、急停、重连为零。当前只完成主机模拟测试。
- 阶段 B：输出接示波器/逻辑分析仪，动力断开。测量解锁、最大/最小范围、DISARM、ESTOP、关蓝牙、杀 App、移出范围、半帧、持续文本、TX 堵塞、复位、棕断的波形。用硬件独立监测记录停止延迟。
- 阶段 C：确认 ESC 文档和停止波形，拆掉桨叶/负载、固定电机、限流供电、有物理断电装置，先零油门，再低油门短时验证；不得直接满油门试验。
- 验收：所有启动/断线/异常/重连场景输出均保持或回到已验证停止信号；急停确认后任何油门和重复包不能重启；RESET 之后还需新 ARM；非法输入不改变输出或续期。分别至少 100 次断连/重连与急停循环，零次非预期启动。
- 必须在风险评估中给出硬件停止时间上限（不大于 1.5 秒；机械系统若要求更快则从严），所有故障注入实测满足该值且独立失联保护在 Python/BLE 卡死时仍有效，否则不通过。保存固件/ESC 型号、接线图、电源参数、原始波形与每次延迟，不能用协议单测替代。
